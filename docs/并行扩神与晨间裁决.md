## 三、改「同时在线 ≤4」

**原意**：一人协调时，聊天窗口太多会**混线、空转、重复派活**——不是硅基算力不够。

**新制（弘尊 2026-05-20 核准）：**

1. **并行当值无硬顶**：诸神可同时各有工单，**工作量越大，同时忙的神越多**。  
2. **不乱**靠流程，靠人数：  
   - 一派工一专窗一工单号  
   - 产出落 `deliverables/<神>/` 或 `tasks/闻仲-工单-*.md`  
   - **未经晨间裁决的「动外物」**（push、改生产、花钱）闻仲不执行  
3. **姜子牙**每日汇总 → **晨间裁决单** → 你批「准/续议/否」→ 闻仲等执行  

铁律「神可以多不能乱」保留；**删除「建议 ≤4」之硬 cap**。

## 四、隔夜工单 · 你早上该看到什么

**目标**：你上线 → 打开 `tasks/晨间裁决-YYYY-MM-DD.md` → 一堆**建议、草稿、待批**，不是空白。

**怎么做到（诚实）：**

| 方式 | 说明 |
|------|------|
| **A · 诸神专 Agent 夜班** | 睡前姜子牙写好 `tasks/隔夜工单.md`；你或殿址机开 N 个 Cursor Agent（比干/吴道子/张良…）各 @ 自己 prompt，让它们落盘 |
| **B · 姜子牙本对话代汇总** | 你睡后无法自动跑 Cursor；可约定「封卷前启动夜班」：姜子牙在本会话用多轮产出各神草稿入 `deliverables/`（**须标「待神确认」** 直至该神专会话过一遍） |
| **C · 脚本** | 柏鉴 `memory_keeper.py` + cron：自动摘要（无 LLM 或接 API 以后再说） |

**优先 A + C**：A 出活，C 保底摘要。
