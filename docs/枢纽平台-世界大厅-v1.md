## 二、枢纽大厅里有什么（职能）

### 1. 世界入口（核心）

访客（或登录用户）在 3D 广场里走向不同 **传送门 / 拱门 / 站台**，进入对应子世界：

| 世界线（示例） | 气质 | 首版 |
|----------------|------|------|
| 古代华夏 | 宫殿、山水、甲胄 NPC | 可先做 **1 个可进** 的 demo |
| 未来都市 | 霓虹、全息牌 | 先做 **门牌 + 预告**（锁） |
| 东亚意境 | 庭院、灯笼、竹径 | 门牌 |
| 欧洲古典 | 石拱、广场、钟楼 | 门牌 |

**不同的人去不同入口** — 需要 **偏好/账号**（O2）：记住上次去的 world_id，或注册时选「主世界」。

### 2. 职能部门（平台级，各世界共用）

| 职能 | 在 3D 里长什么样 | 背后接什么（硅基可自动化） |
|------|------------------|---------------------------|
| **商店** | 摊位 / 橱窗 NPC | 商品表 JSON → 赵公明范蠡 SKU；支付仍 **弘尊碳基** 收款码 |
| **客服** | 服务台 NPC + 对话泡 | 先链 **FAQ + 留言表单**；复杂转弘尊或日后真人 |
| **工作人员 NPC** | 导览、秩序、活动播报 | 台词脚本 + 可选接大模型（殿址机以后）；**不**假装全是真人 |
| **封神公务**（可选） | 「榜亭」「诸神殿」作为枢纽内建筑 | 读 `tasks/` 摘要只读；弘尊专属区需身份 |

## 三、为什么要 3D（产品理由）

- **选世界**用空间表达比下拉菜单更符合「我去古代还是去未来」的直觉。  
- **商店 / 客服 / NPC** 需要「走过去办事」的沉浸感，和灵台、GitHub 彻底切开。  
- 后续 UGC、活动、多人同屏都挂在 **同一枢纽** 上扩，避免每个世界各做一套首页。

**不是**第一版就上万人 MMO；第一版是 **可走的 3D 广场 + 可点的门与职能点**。

## 四、技术路线（网页 3D，免安装）

| 项 | 选择 | 理由 |
|----|------|------|
| 运行时 | **浏览器 WebGL** | 与 GitHub Pages / 门同部署；访客手机点开即用 |
| 引擎 | **Three.js**（或 Babylon.js 二选一 PoC） | 开源、资料多、真姜子牙可本窗写原型 |
| 美术 | 低多边形广场 + 4 拱门 + 3 个职能亭；资产可 **购模 / AI 辅助 / 吴道子定风格** | 全定制建模周期长 |
| 性能 | 首版单场景 &lt; 5MB、移动端 30fps 目标 | 过高模会卡手机 |

**Unity WebGL**：画质好但包体大、加载慢，作 **备选**；首版优先 Three.js 枢纽 PoC。

**NPC**：第一版 = 固定点位 + 点击弹出面板（商店列表 / 客服表单 / 导览文案）；第二版再接语音或 Agent。

## 八、建成什么样才叫「代表绿洲」

| 层 | 观众看到什么 |
|----|----------------|
| **门** | 虚夜、进门仪式（已有） |
| **枢纽** | **大广场 3D**：四门（古/未/东/欧）+ 商店亭 + 客服台 + 导览 NPC；气质待你定（封神广场 vs 科幻航站楼） |
| **子世界** | 进门后 **另一套场景与规则**（第一个建议 **古代华夏** demo）；绿洲感 = **枢纽 + 至少一扇门里真有景** |

只有枢纽、没有可进子世界 → 像「空机场」；只有静态页 → 不像你要的绿洲。目标形态是：**机场（枢纽）+ 星球（子世界）**。
