## 目标（大白话）

弘尊说 **「派单诸神」** 或在本机跑一条命令（如 `python3 scripts/dispatch_gods.py`）时：

1. 自动找到 **最新** 的 `tasks/诸神-立即落实-YYYY-MM-DD.md`（优先今天日期，否则目录取最新）。
2. 按下面 **神名 ↔ 章节** 表，从 md 里抽出各神 **派单块**（代码围栏内整段）。

4. 失败时：PushPlus/物质提醒 + 在终端或日志里打印 **应手贴的文件路径**，方便弘尊兜底。

**姜子牙验收**：脚本/README/配置路径是否落盘；跑一轮后 `memories/` 或 `deliverables/闻仲/` 有「派单已发 / 失败清单」记录。

## 阶段（闻仲主责）

### A · 调研（SDK 能否 multi-agent prompt）

依据 [`@cursor/sdk` SKILL](https://cursor.com/docs/api/sdk/typescript)（姜子牙 2026-05-23 摘录）：

| SDK 形态 | 用途 | 多神派单 |
|----------|------|----------|
| `Agent.prompt(...)` | 一发一收、脚本退出 | 可对每个神 **循环** 调一次（并行用 `Promise.all` / 多进程） |
| `Agent.create(...)` + `agent.send(...)` | 已有专窗、要多轮 | 每个神 **resume 已有 agentId** 或 create 后 send；须 `Symbol.asyncDispose()` |
| `Agent.resume(agentId, ...)` | 跨进程续聊 | **推荐**：弘尊已开的诸神窗，映射 ID 后 resume + send |

**结论（调研交付物）**：SDK **无**内置「派单诸神」一键 API；multi-agent = **N 次** `prompt` 或 `resume`+`send`。闻仲在 `scripts/dispatch_gods_README.md` 或本工单末尾记：**选哪种 + 是否需要 Node 薄封装**。

另查：Cursor **Automations**（触发器定时/手动）能否调同一 prompt 模板 — 若比裸 SDK 稳，可记为 B 备选。

### B · MVP · `scripts/dispatch_gods.py`

1. 解析最新 `tasks/诸神-立即落实-*.md`，按上表抽派单块。  
2. 读 `dispatch_gods_config.json`（神名 → agentId；缺 ID 的跳过并记日志）。  
3. 对每个神调用 SDK/HTTP **发送派单正文**（实现细节 A 阶段定）。  
4. 输出：`deliverables/闻仲/派单日志-YYYY-MM-DD.md` 或 `memories/` 一行 — 成功/失败/跳过列表。

**弘尊触发**：

```bash
cd ~/Jiangziya/jiangziyamemory
python3 scripts/dispatch_gods.py
# 或带 --dry-run 只打印将发谁
```

姜子牙口令 **「派单诸神」** = 提醒弘尊跑上式或日后 cron；**不是**姜子牙代发（除非日后 hook 接好）。

### C · 失败兜底

任一下列情况 → **PushPlus 一条** + stderr 打印：

- 无 API key / 401  
- 某神无 agentId  
- send 失败 / 超时  

消息含：`tasks/诸神-立即落实-YYYY-MM-DD.md` 路径 + 失败神名列表 +「请手贴该神派单块」。
